Goal: Phase 1.5 for timui.h - complete the next library/platform sweep: Windows
ConPTY backend; submit-capable textarea; autocomplete/combobox; toast/
notification; split/resizable panes; TCSS-like stylesheet; grapheme clustering;
and protocol-neutral images with Sixel + iTerm2, while keeping the larger
architecture/app work as Phase 2 backlog only.

READ FIRST:
- AGENTS.md / CLAUDE.md project rules. Work only through `nix develop -c make <target>`.
- `docs/backlog.md` Phase 1.5 and Phase 2 sections.
- `docs/gaps.md` "Selected for Phase 1.5".
- `docs/TERMINAL_PROTOCOLS.md`, `docs/API.md`, `docs/DESIGN.md`.
- Existing goal context: `docs/goals/widgets-layout.goal.txt`,
  `docs/goals/chat-multiline.goal.txt`, and `docs/goals/vt-gif-v2.goal.txt`.

NON-GOALS FOR THIS PHASE:
- Do not build Matrix, SimpleX, or the Chez/Pi agent harness.
- Do not introduce an Elm/component framework yet.
- Do not build global keybinding/vim-mode infrastructure yet.
- Do not make broad focus traversal or global mouse-drag architecture the scope.
  Local splitter drag is allowed only as much as resizable panes require.
- Do not claim Windows graphics support as a ConPTY feature. ConPTY is a
  transport/backend; graphics are chosen by terminal image protocol capability.
- Do not hand-roll crypto. This phase should not need crypto at all.

RECOMMENDED ORDER:
- ConPTY can proceed independently if a Windows-capable environment is
  available; otherwise capture the blocked smoke gate and continue with the
  portable work.
- Do grapheme clustering before text-heavy widgets. It affects textarea
  cursor/delete, input fields, combobox filtering, cell fitting/truncation,
  table/tabs/code rendering, snapshots, and vt_gif parity.
- Define the stylesheet parser/resolver before finalizing the new visible
  widgets, so comboboxes, toasts, and splitters do not bake in hard-coded style
  choices that the style layer immediately has to undo.
- Promote `timui_text_area` after grapheme semantics are clear. Then build
  autocomplete/combobox on input-field/listbox/command-palette machinery.
- Add toast/notification after the style layer has severity/state conventions.
- Add split/resizable panes once the minimal local drag path is defined.
- Generalize the image backend before adding Sixel/iTerm2 emitters; Kitty stays
  the known-good path throughout.

WORKSTREAM B - Widgets:
- Textarea first. Add a result-returning controlled API, plus `_mut`
  convenience, while keeping the current `timui_text_area` wrapper compatible.
  Return at least changed/submitted/focused state. Define Enter vs newline
  semantics explicitly. Shift+Enter is only reliable when the terminal reports
  modifiers, so document fallback behavior. Preserve paste newlines; if the
  current paste sanitization drops them before widgets see them, fix that with a
  failing regression test first. Refactor `examples/chat.c` and `examples/irc.c`
  to use the library submit event.
- Autocomplete/combobox. Caller owns options and state. Support query editing,
  open/closed state, selected row, scroll, keyboard navigation/accept/cancel,
  mouse accept, clipping, UTF-8 labels, empty list, duplicate labels, and
  cap-limited query buffers.
- Toast/notification. Keep immediate-mode: caller owns notification data. Draw
  severity, TTL/expiry, stacking, clipping, and manual dismiss. No hidden global
  notification manager.
- Split/resizable panes. Build on `timui_split`/`timui_split_ex`, with
  caller-owned split state and local divider drag. Test min/max/ratio clamp,
  release-outside behavior if implemented locally, and degenerate rectangles.
- Acceptance: positive + negative/adversarial tests for every widget; gallery
  demonstrates the new widgets; chat/IRC composer workarounds are gone.

WORKSTREAM C - Declarative style layer:
- Add a small TCSS-like parser/resolver over existing `TimuiStyle` and theme
  slots. Keep it optional; existing theme APIs continue to work.
- Initial selector scope: widget kind, `#id`, `.class`, and states such as
  `:focused`, `:hovered`, `:active`, `:disabled` if supported.
- Initial properties: `fg`, `bg`, attrs (`bold`, `dim`, `reverse`), `border`,
  `padding`, `gap`, and gradient endpoints where they map cleanly to existing
  drawing primitives.
- Implement deterministic cascade: simple specificity and source order. Avoid
  full CSS inheritance, layout reflow semantics, imports, or units beyond what
  the current layout/style system can defend.
- Acceptance: parser positive/negative tests, malformed input tests, unknown
  property behavior, specificity/order tests, OOM tests, and snapshot examples
  applying styles to real widgets.

WORKSTREAM D - Grapheme clustering:
- Implement generated Unicode grapheme-break data/helpers rather than ad hoc
  string slicing. Add helpers for next/prev cluster and cluster display width.
- Integrate into input field, textarea cursor/delete, `timui_fit_cell`, table
  truncation, code/rich text paths, and snapshot/rendering width decisions where
  applicable.
- Test ZWJ emoji, skin tones, flags/regional indicators, combining marks, VS16,
  CRLF, malformed UTF-8, empty strings, cap boundaries, and truncation with an
  ellipsis.
- Acceptance: no widget cursor/delete/truncation path splits an extended
  grapheme cluster in the covered vectors; existing width/bidi tests remain
  green. Replace any codepoint-width invariant that no longer holds with an
  explicit cluster-width invariant.

WORKSTREAM E - Protocol-neutral images, Sixel, iTerm2:
- DONE: Refactor `src/timui_kitty.c` into the protocol-neutral
  `src/timui_images.c` layer while keeping the public `timui_image_*` API
  stable.
- DONE: public `TimuiImageProtocol`, `timui_caps_image_protocol`,
  `timui_image_protocol`, and `timui_force_image_protocol` are in place. Kitty
  behavior is preserved, non-Kitty image protocols deliberately draw the
  placeholder until emitters exist, and stale Kitty placements are cleared when
  forcing images off.
- DONE: iTerm2 inline image emission is implemented for unclipped PNG draws via
  OSC 1337, including stale Kitty placement cleanup when switching from Kitty to
  iTerm2 and placeholder fallback for clipped iTerm2 draws.
- DONE: Sixel emission is implemented for raw RGBA images with an exact
  16-colour palette cap and alpha thresholding.
- DONE: RGBA and plain-PNG Sixel clipped draws crop the source pixels and emit
  cropped DCS payloads; malformed/oversized PNGs still fall back.
- DONE: raw-RGBA palettes above 16 opaque colours are quantized to a bounded
  deterministic 16-colour terminal palette instead of falling back.
- DONE: raw-RGBA Sixel draws scale to the requested cell rectangle when terminal
  cell-pixel geometry is known from `TIOCGWINSZ`; otherwise they preserve source
  pixel dimensions.
- DONE: `TIMUI_NO_IMAGES` is active as an API-preserving no-image-emission mode:
  image caps/protocol forcing select `NONE`, and image draws render `[img]`
  without terminal image escapes.
- DONE: `timui_image_from_png_rgba` preserves PNG bytes for Kitty/iTerm2 while
  giving Sixel caller-decoded pixels for emission and clipping.
- DONE: Plain PNG images forced to Sixel are lazily decoded through a bounded
  PNG-only `stb_image` path and then emitted through the same RGBA Sixel encoder.
- DONE: `make smoke-image-live PROTO=... FRAMES=N` exists for live
  Kitty/Sixel/iTerm2 visual evidence capture, and `make check-image-smoke`
  checks the harness headlessly without claiming protocol evidence. The accepted
  operator procedure is `docs/runbooks/phase1-5-live-evidence.md`.
- DONE: iTerm2 terminal evidence via hosted macOS iTerm2 run `28986249841`.
- DONE: Windows ConPTY smoke evidence via hosted Windows run `29226547099`.
- Preserve Kitty behavior and fallback placeholder behavior. The public image
  API has PNG, raw-RGBA, and PNG+RGBA sidecar constructors; Sixel uses decoded
  pixels from raw RGBA, sidecars, or the bounded plain-PNG decoder.
- Add capability selection for Kitty, Sixel, iTerm2 inline images, and none.
  Sixel should be prioritized before iTerm2 because it is useful for Windows
  Terminal and classic terminal compatibility.
- Research and record any encoder dependency and license before vendoring or
  linking it. Do not casually add a large dependency.
- Acceptance: protocol emission tests, fallback tests, clipping/placement tests,
  no regression in `make check-vt-gif-all`, and docs that state exactly which
  protocol is supported where.
